## 1. Approach Explanation

The solution is designed as a modular system with two primary engines and a fully gamified web interface:

1.  **Student Query Understanding (Q1):**
    *   **Goal:** To interpret natural language questions and extract intent, topic, and difficulty.
    *   **Method:** We utilize a Large Language Model (LLM) prompts engineered to act as an educational classifier. Instead of relying solely on keyword matching or separate BERT embeddings, the LLM provides contextual understanding, able to differentiate between a student asking for an "Explanation" vs. an "Example".

2.  **Adaptive Learning Path Recommendation (Q2):**
    *   **Goal:** To recommend the next logical step based on student performance.
    *   **Method:** A hybrid approach combining rule-based logic (curriculum sequencing) with LLM reasoning. The system evaluates metrics (Score, Attempts, Time) against pedagogical rules to determine if a student needs revision or advancement.

3.  **Gamified Learning Interface:**
    *   **Goal:** To maximize student engagement through interactive, game-like learning activities.
    *   **Method:** A Streamlit-based web dashboard with six interactive tabs featuring XP rewards, level progression, badges, streak tracking, and multiple game modes.

## 2. Dataset Source & Generation

**Source:** Synthetic Data Generation (Self-generated)
**Reason:** No public dataset was provided that perfectly matched the multi-turn interaction required for adaptive learning paths.

**Generation Logic:**
*   A Python script (`data/synthetic_data_generator.py`) simulates student interactions.
*   **Fields:** `student_id`, `topic`, `quiz_score` (Normal distribution centered at 70), `attempts` (correlated inversely with score), `time_spent`, `last_asked_intent`.
*   **Volume:** Configurable, defaulting to 100 students with 5-20 interactions each.
*   **Privacy:** The data is entirely synthetic and contains no PII (Personally Identifiable Information).

**Flashcard & Quiz Data:**
*   **MCQ Data:** 35 hand-crafted multiple-choice questions across 7 ML/AI topics (5 per topic), each with 4 options, correct answer index, and detailed explanation. Stored in `src/flashcards.py`.
*   **Memory Game Pairs:** 42 concept-definition pairs (6 per topic) for the Memory Match Game, also in `src/flashcards.py`.

## 3. Model Architecture

**Core Model:** Llama-3.3-70b-versatile (via Groq API)

### Schema:
*   **Input:** Natural Language Query OR Student State Dictionary.
*   **Processing:**
    *   **System Prompt:** Defines the persona (e.g., "You are an AI academic advisor").
    *   **User Prompt:** Wraps the input with specific constraints (e.g., "Output only JSON", "Classify into...").
*   **Output:** Structured JSON.

### Flow:
1.  User Input -> `main.py`
2.  `main.py` -> `StudentQueryEngine.analyze_query()` -> LLM -> JSON
3.  `main.py` -> `AdaptiveLearningEngine.recommend_path()` -> LLM -> JSON

## 4. Gamification & Interactive Features

### 4.1 XP & Level System
*   Students earn XP through all interactions: answering quizzes (+15 XP correct, +3 XP attempt), matching memory pairs (+10 XP), studying cue cards (+3 XP), and completing challenges (+25-75 XP bonus).
*   Level progression: Curious Learner -> Active Student -> Quick Thinker -> Knowledge Builder -> Rising Star -> AI Enthusiast -> ML Specialist -> Deep Thinker -> Neural Master -> AI Grandmaster.

### 4.2 Memory Match Game
*   A 4×3 grid of 12 face-down cards (6 concept-definition pairs per topic).
*   Students flip two cards at a time; matching concept↔definition pairs stay revealed.
*   Tracks moves, awards XP per match (+10), and bonus XP on completion based on move efficiency.
*   Star rating (1-5★) based on total moves used.

### 4.3 Cue Cards
*   Traditional flip-style study cards with concept on front, definition on back.
*   Previous/Flip/Next navigation through 6 cards per topic.
*   Follows the same topic selection as the Memory Game.
*   +3 XP per card studied for active recall reinforcement.

### 4.4 Daily Quiz
*   5-question adaptive quizzes generated by the LLM based on the selected topic.
*   Immediate correct/wrong feedback with detailed explanations.
*   Animated score reveal with stars and XP rewards.

### 4.5 Badges & Streaks
*   Achievement badges: First Steps, Quiz Master, Knowledge Explorer, etc.
*   Daily streak tracking with fire icon indicator.
*   Badge popup animations on unlock.

### 4.6 Study Roadmap
*   Visual learning path through 7 ML/AI topics.
*   Topics unlock sequentially as students complete memory game decks.
*   Shows completion status, estimated time, and key concepts per topic.

## 5. Assumptions and Limitations

**Assumptions:**
*   The student is studying a fixed curriculum (Linear Regression -> ... -> RNNs).
*   Quiz scores are the primary metric for understanding.
*   The API availability is constant.

**Limitations:**
*   **Dependency on LLM:** The system requires an active internet connection to query the Groq API.
*   **Statelessness:** The current implementation processes each request independently (though the batch processor simulates history). A production version would require a persistent database.
*   **Curriculum Scope:** The current topic list is hardcoded for the demo.

## 7. System Design

*   **Modular Codebase:**
    *   `src/`: Contains the intelligence engines (`query_engine.py`, `adaptive_engine.py`), gamification system (`gamification.py`), flashcard data (`flashcards.py`), and UI styles (`styles.py`).
    *   `data/`: Handles data generation.
    *   `app.py`: Streamlit web interface with 7 interactive tabs.
    *   `main.py`: CLI entry point.
*   **Scalability:** The use of class-based engines allows for easy integration into a web backend (Flask/FastAPI) in future iterations.
